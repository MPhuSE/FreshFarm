1. Tổng quan API
1.1 Mục tiêu
API v1 cung cấp dữ liệu và nghiệp vụ cho hai nhóm giao diện: Storefront dành cho khách hàng và Admin Dashboard dành cho Staff/Admin. API chịu trách nhiệm xác thực, phân quyền, kiểm tra nghiệp vụ, tính toán tiền, bảo toàn tồn kho và trả dữ liệu theo một contract thống nhất.

3. Xác thực và phân quyền
3.1 Cơ chế đề xuất
MVP dùng Laravel Sanctum theo Bearer Token hoặc session cookie tùy cách tổ chức frontend. Nếu Blade chạy cùng domain với Laravel, session + CSRF là lựa chọn đơn giản. Nếu Frontend tách riêng, dùng Sanctum token và CORS whitelist.
Mật khẩu được hash bằng password_hash/Bcrypt hoặc Argon2; không bao giờ trả password_hash/remember_token.
Tài khoản status=locked không được đăng nhập và token/session cũ nên bị thu hồi khi khóa.
Route /admin luôn kiểm tra role/policy tại server; ẩn menu không thay thế authorization.
Login giới hạn tần suất theo email + IP; lỗi không tiết lộ email có tồn tại hay không.

8. Luồng nghiệp vụ xuyên suốt
8.1 Luồng mua hàng
1.  Khách đăng ký/đăng nhập và lấy trạng thái người dùng hiện tại.
2.  Frontend gọi catalog để lọc, phân trang và mở chi tiết sản phẩm.
3.  Khách thêm sản phẩm vào giỏ; Backend lấy giá và tồn kho từ database.
4.  Checkout preview tính lại subtotal, discount, shipping_fee và grand_total.
5.  Frontend gửi create order cùng Idempotency-Key; Backend chạy transaction và khóa tồn.
6.  Khách nhận order_code; Admin xác nhận, chuyển shipping và delivered theo ma trận.
7.  Sau delivered, khách được phép tạo một đánh giá cho mỗi order_item.

10. Bảo mật và vận hành
Chủ đề
Yêu cầu bắt buộc
Input
Form Request validation; whitelist sort/filter; giới hạn độ dài; không mass assignment ngoài fillable.
SQL
Eloquent/query builder hoặc prepared statement; tuyệt đối không nối input vào SQL.
Authorization
Middleware auth + role/policy + ownership scope; Admin route kiểm tra ở server.
Secrets
Không commit .env; không log password/token; key production nằm trong secret manager/environment.
Response
Không trả password_hash, remember_token, stack trace, SQL, đường dẫn nội bộ hoặc token không cần thiết.
CORS/CSRF
CORS whitelist origin; session flow dùng CSRF; cookie Secure/HttpOnly/SameSite phù hợp.
Rate limit
Login và thao tác nhạy cảm có throttle; trả 429 với error_code ổn định.
Logging
Mỗi lỗi có trace_id; log actor, route, status và thời gian; che dữ liệu nhạy cảm.
Upload
MIME whitelist, size limit, random filename, storage riêng và cleanup orphan.
Backup
Có schema + seed; backup trước migration; kiểm tra khả năng restore.
11. Hiệu năng và database
Eager load category, primary image và inventory khi trả catalog; kiểm tra không phát sinh N+1.
Index foreign key và cột dùng filter/sort thực tế; dùng EXPLAIN cho products, orders và report.
Pagination mặc định 12 cho storefront, 20 cho admin; per_page tối đa 100.
Catalog lớn có thể chuyển sang cursor pagination theo id/created_at sau MVP.
Transaction chỉ giữ lock trong thời gian ngắn; thống nhất thứ tự khóa để giảm deadlock.
Report aggregate chỉ tính đơn hợp lệ và giới hạn khoảng ngày để tránh truy vấn không kiểm soát.

14. Versioning và quản lý thay đổi
Non-breaking: thêm field nullable/optional, thêm endpoint, thêm error_code có tài liệu; vẫn cần thông báo FE.
Breaking: đổi tên/xóa field, đổi kiểu dữ liệu, đổi nghĩa status, thay cấu trúc envelope; phải tạo /api/v2 hoặc có giai đoạn tương thích.
Mọi Pull Request thay contract phải cập nhật tài liệu và test contract trong cùng nhánh.
Có thể dùng header Deprecation/Sunset khi ngừng endpoint trong giai đoạn sau MVP.
